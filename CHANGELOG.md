# Changelog

All notable changes to RoboDR are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
(pre-1.0: any minor or pre-release may change interfaces).
A release is cut by tagging `v<VERSION>`. `.github/workflows/release.yml`
requires a `## [<VERSION>]` section here and uses it as the release notes.

## [Unreleased]

### Security (closing documented gaps, 2026-10-30)

- **Black-box key rotation without a hand-edited log:** `robodr-blackbox
  rotate` writes a KeyRotation record and the chain continues under the new
  key; `robodr-agentd` reads retired public keys from
  `blackbox.previous_keys` (also for the TPM anchor sidecar and the profile
  anti-rollback scan) and refuses to start if one is missing (OPERATIONS 4.3).
- **Legacy HMAC-SHA256 keys are refused by default** in `robodr-blackbox`,
  `robodr-agentd`, `robodr-replay` and `robodr-deliverd`: opt in with
  `--allow-hmac` or `blackbox.allow_hmac: true`. **Upgrade note:** a unit
  still on an HMAC key must opt in or migrate (`rotate --allow-hmac`,
  deliverd `rekey`) before upgrading.
- **Sealed control-plane state:** the request journal and replay store
  (`robodr-cp-journal/v2`) are an HMAC chain under a key derived from the
  black-box key, with their end points in signed black-box notes. An edited,
  deleted, truncated or rolled-back journal is quarantined and rebuilt from
  the black box, the replay store is fenced, and
  `robot.agent.control_plane_state_untrusted` (High; Critical for a
  rollback) is raised. v1 journals upgrade once, automatically. The executor
  seals `journal.json` and `soc_nonces.json` and refuses orders after a
  journal reset until `rearm`; `robodr-executor seal-journal` upgrades an
  existing journal (run as `robodr-exec`, OPERATIONS 6.5).
- **Failed reverts are findings:** `robot.agent.executor_revert_failed`
  (High) and `robot.agent.executor_journal_reset` (High). Findings contract
  **2.4.0**.
- **Certificate revocation (CRL) on every TLS path:** control plane mTLS
  (`tls.crl_files`), remote head anchor client and receiver, Kafka
  (`--tls-crl-file`), uplink (`--crl-file`) and enroll (`soc.crl_files`).
  Fails closed (missing issuer CRL, expired or unusable CRL); files are
  reloaded on change without a restart; counters in status. TLS clients with
  CRLs no longer resume sessions (a resumed session skipped the revocation
  check). OCSP is not supported, by design, for air-gapped fleets.
- **No indexing panics in the daemons:** `robodr-agentd`, `-executor`,
  `-export`, `-firewall-gw`, `-deliverd` and the parsers they run on
  untrusted input (`-rtps`, `-capture`, `-cdr`, `-pkg`, `-ros2-pipeline`)
  deny `clippy::indexing_slicing` in non-test code; about 530 sites were
  rewritten to checked access, so a short or inconsistent packet, file or
  response takes the existing malformed / refused path instead of aborting
  under `panic = "abort"`. Wire formats and decisions are unchanged.
- **SIEM verification status cannot be forged through a dotted key:**
  `integrations/verify/robodr_verify.py` rejects a finding whose top-level
  keys are not the contract's; the Elastic `robodr-findings-verified`
  pipeline refuses a document with a dotted top-level key (a literal
  `robodr_verified_by_forwarder.status` used to merge into the verifier's
  status); Splunk's verified sourcetype reads a multivalue status as
  `malformed`. The verifier now rejects any malformed record on its own
  instead of crashing the run, and accepts only the producer's compact
  signature header form, as the Rust parser now also requires.

### Changed (exporters)

- `robodr-kafka-publish`'s producer is **idempotent by default**
  (InitProducerId, per-partition sequence numbers, a batch journal in the
  progress file): a chunk re-sent after a lost acknowledgement or a crash is
  dropped by the broker. `--no-idempotence` keeps at-least-once for brokers
  without the IDEMPOTENT_WRITE ACL. Not tested against a real broker in this
  change (`scripts/kafka-it.sh` not run).
- The exporters prune their own `done/` markers (default 30 days), rotated
  dead-letter files (`--dead-letter-*`) and, opt-in, `robodr-spool-export`'s
  rejected records, never deleting anything still needed for deduplication.

### Added (packaging and operations, 2026-10-30)

  written source offer for the Pulsar eBPF probes
  (`GPL-2.0-SOURCE-OFFER`), generated by `scripts/third_party_notices.py`

  release workflow reads the repository variable `ROBODR_MAINTAINER`.

  be restored (anti-rollback, replay and TPM-bound state).

### Added (packaging and platforms)

- The `robodr` `.deb` is built in an **Ubuntu 22.04** userland (glibc
  2.35), natively for amd64 and arm64, `robodr-pulsard` included (clang-20
  from apt.llvm.org, archive key pinned by fingerprint): it installs on
  Ubuntu 22.04 / NVIDIA JetPack 6, Debian 12 and newer. Before, it was
  built on Ubuntu 24.04 and needed glibc 2.39. `Depends:` now comes from
  `dpkg-shlibdeps` plus a soname table (an unknown library fails the

- **RPM** for RHEL / Rocky / Alma 9 and Fedora (`packaging/build-rpm.sh`,
  `packaging/rpm/`): built on Rocky Linux 9 (glibc 2.34), the `.deb`'s file
  tree (`build-deb.sh --stage-only`), `%config(noreplace)` for
  `pulsar.toml`, scriptlets equivalent to the maintainer scripts, rpm's
  generated ELF requirements. Released with its own `SHA256SUMS-rpm-<arch>`
  and minisign signatures; no OpenPGP signature yet (offline bundle: see
  "Added (packaging and operations)" above).
- External BTF for kernels without it (NVIDIA L4T): the
  `robodr-pulsard` unit accepts `/etc/robodr/btf/vmlinux` (Pulsar's
  `[pulsar] btf_path`, commented in `pulsar.toml`) instead of
  `/sys/kernel/btf/vmlinux`, and `robodr-btf-check` refuses to start with
  any other `btf_path`, or a file whose stamp names another kernel build
  or another SHA-256. Generation with `pahole`:
  `docs/UNITREE.md` 3.2.1.
- `robodr-focal`: a systemd 245 variant of the Kafka TLS / SASL credential
  drop-in example (`robodr-load-credential` instead of `LoadCredential=`).
- CI: `package-deb`, `package-rpm` (container jobs per architecture, with
  the reproducibility proof in the build userland) and `package-smoke`
  (apt / dnf installs in Debian 12, Ubuntu 20.04 / 22.04 / 24.04, Rocky
  Linux 9 and Fedora 42 containers, `scripts/pkg-install-smoke.sh`).
  `release.yml` builds the same way, smoke-installs before signing, and
  its build jobs no longer hold `contents: write`.
- `scripts/check-packages.py`: every workspace program classified per
  package variant, every `ROBODR_DEB_REQUIRE` list complete, deb and rpm
  scripts handling the same units, and built packages compared (paths,
  modes, content, ownership, no setuid / group-writable file, no private
  key material). `scripts/check-focal-units.py` also checks the regular
  drop-in examples that `robodr-focal` ships unchanged.

### Fixed (packaging)

- CI's `robodr-focal` build did not require `robodr-executor` and
  `robodr-firewall-gw` (the release did): a CI package could lack them.
- `robodr-focal` shipped the Kafka credential drop-in example with
  `LoadCredential=`, which systemd 245 ignores.
- `build-deb.sh` created man pages with the caller's umask: under umask
  000 (as in a container) they were world-writable in the package. It now
  sets umask 022 and the mode explicitly.
- The `.deb`'s `prerm` did not stop `robodr-deliverd` on removal.
- `scripts/deb-install-smoke.sh` used `cp --update=none` (coreutils >= 9.3).
- Removal left services enabled, so a reinstall started them at the next
  boot before commissioning: RPM erase now disables them, deb purge
  removes their `.wants` / `.requires` links (masks and drop-ins stay).
- `robodr-pulsard.service` set `SecureBits=noroot-locked` without
  `AmbientCapabilities=`, so the daemon would have run without any
  capability (no `CAP_BPF`): the ambient set now equals the bounding set.
- The pinned clang of ring now also pins the LLVM libraries that hold its
  code generator (`libllvm*`, `libclang-cpp*`, ...), not only the driver.

### Added (Unitree coverage gaps)

  fixed-point values round to the safe side. Values outside `i16` are
  suppressed, and holds use the last accepted frame.
- `robodr-firewall-gw`: codec `unitree_a2_lowcmd` (the go `LowCmd_` path
  with `require_crc`, a type recorded in the profile, no bypass and no
  battery off).
- `robodr-ros2-pipeline`: `webrtc` monitor for Go2 WebRTC control
  sessions. It reads the signalling metadata, ICE, TURN and DTLS headers,

- `robodr-firewall-gw`: a `webrtc` section. It feeds the monitor from
  NFLOG copies, can drop unlisted signalling (`block_unlisted`) and
  provides quarantine sets by peer or flow. `webrtc-block` prints the

- Findings contract 2.3.0, Unitree block (§3d):
  `robot.unitree.webrtc_unknown_controller`, `webrtc_new_peer`,
  `webrtc_controller_mac_mismatch`, `webrtc_session_in_denied_window`,
  `webrtc_concurrent_sessions`, `webrtc_relayed_session`,
  `webrtc_media_without_signalling`. agentd's `gateway_feed` accepts them.
- Fuzz targets `go1_compressed_lowcmd` and `unitree_webrtc`.
- Review fixes, WebRTC monitor:
  - Findings are deduplicated per peer session, so a returning peer is
    reported again.
  - Non-Critical findings are rate limited per minute with an aggregate
    count. The Critical established-session finding is never suppressed.
  - Eviction prefers single-packet, non-established peers.
- Review fixes, gateway:
  - It passes `NFULA_HWADDR` to the monitor, so the MAC binding of

  - A top-level `robot_model` cross-checks the A2 / AS2 channel.
- Review fixes, agentd: the feed accepts exactly the monitor's WebRTC

### Security

- Wave-2 soak and red team (2026-10-30, `tools/e2e/RESULTS.md`): agentd's
  `gateway_feed` accepts only rule ids of the findings catalog
  (`robodr_ocsf::builder::rule_known`); before, a line naming
  `robot.firewall.` or any made-up `robot.gateway.*` / `robot.firewall.*`
  id became a finding with the generic catalog entry. The inline
  gateway's housekeeping reports a WebRTC flood's "N further ...
  suppressed" aggregate once its minute is over
  (`WebRtcMonitor::tick`); before, it waited for the next packet, so a
  flood followed by silence was reported as its first 32 findings only.
- The inline gateway's findings feed sends a heartbeat line
  (`robodr-gateway-heartbeat/v1`) every 5 s while idle and agentd accepts
  it as activity (`daemon.gateway_heartbeats`): before, a quiet, healthy
  gateway made agentd report `robot.agent.input_silent` (High, daemon
  state `unknown`) after every `silence_ms` (8 times in the 75-minute
  soak). Upgrade agentd before the gateway.

- Adversarial self-review of Sprints 14a / 14b (`docs/SECURE-DELIVERY.md`
  §10 "Adversarial self-review of 14a/14b"): leases are based on the TPM
  time the unit's AK attests, not on the time a report claims (root on a
  unit could otherwise obtain a lease that never expires); the depot's
  handshake, request head and report body share one deadline (a trickling
  client held a connection slot indefinitely); trust files signed before
  14a keep parsing; a lease renewed in a media pack next to a known
  deployment is installed; units no longer download an unchanged pack
  every pass.

- **Kafka export and remote head anchor over TLS** (R2 / GAP-03). New
  `robodr_blackbox::tls` (rustls + ring, the stack `robodr-uplink` and the
  control plane already use; no new crypto crates): server verification
  always on (the configured CA file only, validity, `serverAuth`, the
  dialled host or an explicit `server_name`: SNI and the verified name are
  the same), optional SPKI pins, optional client certificate (mutual TLS),
  bounded handshakes, key-file mode checks. Test PKI and generator in
  `fixtures/tls/`.
  - `robodr-kafka-publish` / `ProducerConfig`: `--tls-ca`, `--tls-cert`,
    `--tls-key`, `--tls-server-name`, `--tls-spki-sha256`; every broker
    (bootstrap and advertised) verified. SASL/SCRAM-SHA-256 / -512
    (`--sasl-mechanism`, `--sasl-username`, `--sasl-password-file`; over
    TLS only; server signature checked, iteration count bounded, failures
    fatal; broker session lifetimes honoured by reconnecting). Verified
    against Apache Kafka 3.9.1 (SSL, SSL with required client
    certificates, SASL_SSL SCRAM; `scripts/kafka-tls-it.sh`, native, no
    docker) and the fake cluster (`tests/kafka_tls.rs`).
  - Remote anchor: agentd `blackbox.head_anchor.tls` {`ca_file`,
    `server_name`, `server_spki_sha256`, `cert_chain`, `key_file`};
    `robodr-anchor-receiver` `"tls"` {`cert_chain`, `key_file`,
    `client_ca`} (with `client_ca`: mutual TLS, no session resumption).
  - **Breaking: plain TCP is refused unless explicitly allowed.**
    `robodr-kafka-publish` exits 2 without `--tls-ca` or
    `--allow-plaintext`; agentd refuses a `remote` head anchor without
    `tls` or `"allow_plaintext": true`; `robodr-anchor-receiver serve`
    exits 2 without `"tls"` or `"allow_plaintext": true`. TLS together
    with allow-plaintext is refused. No fallback in either direction: a
    TLS client never retries in plain TCP, a TLS server never parses a
    plain request. Upgrade: give the brokers' / receiver's CA (or, on an
    isolated link, add the explicit flag) before upgrading; the
    `robodr-kafka-publish.service` units take `ROBODR_KAFKA_TLS_ARGS` from
    `/etc/robodr/kafka-publish.env` (new drop-in example
    `60-tls-credentials.conf.example` for the client key and the SCRAM
    password).
  - Adversarial tests: untrusted CA, wrong host name, expired
    certificate, certificate without `serverAuth`, pin mismatch, missing /
    foreign client certificate, downgrade both ways, plain TCP refused,
    wrong SCRAM credentials, an impostor broker that cannot produce the
    server signature, a downgraded iteration count, key file modes.
  - Independent review of this work (fixed, each with a regression test):
    a peer trickling one byte per socket timeout held a TLS handshake
    open for ever (the timeout was armed once; rustls loops over reads):
    every anchor-receiver slot (F1), the anchor's delivery thread with no
    failure counted (F2) and the Kafka producer past all its deadlines
    (F3). Every TLS read and write now re-arms the timeout with the time
    left (`tls::DeadlineTcp`); the receiver bounds a connection by
    `io_timeout` and caps connections per source address
    (`max_connections_per_source`, default 8); the anchor bounds each
    exchange as a whole and reports an attempt that outlives its bound.
    TLS key / CA / password files must now be owned by root or the
    process's user and are opened without blocking on a FIFO (F5); secret
    file contents, the SCRAM proof and the SCRAM hash states are wiped
    (F4).
  - Limits: no CRL / OCSP on these paths; mutual TLS authenticates hosts,
    not robot ids (anchor marks stay bound to units by their Ed25519
    signatures); no `PLAIN` / `GSSAPI` / `OAUTHBEARER`; KIP-368 in-band
    re-authentication is replaced by reconnecting; idempotence still off.
  - Build: `robodr-blackbox` now depends on rustls / rustls-webpki, so
    ring's C is compiled for every crate that depends on it
    (`docs/BUILD.md`).
- Adversarial review of Sprint 13c (sealing; `docs/SECURE-DELIVERY.md` §10
  "Adversarial review of 13c"); each fix has a regression test that failed
  before it (`crates/robodr-seal/tests/review_13c.rs`):
  - H1 (high): **a revoked PCR policy worked again on a TPM with an empty
    owner authorization**: root could undefine and redefine the policy
    floor. `robodr-seal provision` now refuses unless the owner and lockout
    authorizations are set (`--owner-auth-file` is required), `policy
    commit` refuses while they are empty, `status` warns. **Units
    provisioned with an earlier build:** set both authorizations
    (OPERATIONS §12.1) before the next `policy commit`.
  - H2 (high): **erasing a unit without a TPM could report success while
    destroying nothing** (UWK file absent because the runtime volume was
    closed). The erase of such a unit is now the LUKS2 keyslot wipe; the
    device is required (`seal.device`, required in `deliverd.json` without
    a TPM; `--device`), and the report and `robot.seal.erased` list exactly
    what was destroyed.
  - M1 (medium): erase now stops `seal.stop_units`, unmounts the runtime
    root and closes `seal.mapper_name`, or suspends it when busy; it used
    to leave an open volume readable.
  - M2 (medium): TPM session contexts (session keys) are written only under
    a tmpfs work directory (`/run/robodr-seal`, checked; `--work-dir`,
    `seal.tpm.work_dir`), never the seal directory, and leftovers of killed
    commands are swept.
  - L1: `enroll-fallback` refuses a key directory that is not on dm-crypt.
    L2: a successful epoch increment with a failed read-back counts as the
    erase. L3: the fallback key and the owner-auth file are opened with
    `O_NOFOLLOW`.
  - `robodr-deliverd.service` reached no TPM (`PrivateDevices=yes`): now
    `DevicePolicy=closed` with `DeviceAllow=/dev/tpmrm0 rw`.

- Third review of the F1 / F3 fixes (`tools/e2e/REDTEAM.md`, "Third
  review of the F1 / F3 fixes"); each fixed finding has a regression test
  that failed before its fix:

  motion monitor's latency / persistence windows, the firewall's rate

  that looks held only because a child forked by another thread still has
  the descriptor (until it execs) is retried for up to 25 x 10 ms before it

    domain (e.g. domain 2 covers 8007 / 8080 / 8082 / 8090).
  - **Command type names (M4).** The profile records the announced type of
    each motion channel (`Profile::motion_types`, optional key, written by
    `robodr-commission learn` where every writer agreed); a writer on a
    profiled command channel announcing another type, an unknown type or a
    feedback type is `robot.motion.command_type_mismatch` (High, at the
    announcement) instead of only a rate-limited Medium per sample.
  - **Firewall channel kind (M1).** `FirewallSettings::from_profile` takes a
    channel's kind from the recorded type (`robodr_agent::channel_kind`,
    `kind_of_type`), not from learned zeros: a twist channel whose learned
    `max_linear_speed` is 0 no longer becomes a joint channel (an alarm
    storm of `rejected_kind_mismatch`). Without a type an ambiguous
    envelope (`max_linear_speed: 0` plus a `max_joint_speed`) is refused
    with a clear message; `FirewallSettings::warnings` says when the type
    had to decide.
  - **Morphology without `robot_model` (M2).** A 35-slot (`unitree_hg`)
    joint channel requires a humanoid firewall platform and policy (every
    hg model is a humanoid); a profile with `/lowcmd`, `/arm_sdk`,
    `/user_lowcmd` or `/api/*` channels and no `robot.robot_model` is
    warned about; slot counts are checked by the recorded `LowCmd_` type
    for any channel name; a legacy channel is refused as a `joint_config`
    channel (legacy frames carry no writer identity the firewall could
    authorise). Decoded legacy `LowCmd` frames now carry their 20-slot
    joint frame.
  - **Response-policy overrides (M6).** The shipped policies overrode
    `robot.host.unexpected_egress` and `robot.motion.unexpected_source`,
    which nothing emits. Host detections all arrive as
    `robot.host.pulsar_threat` (an override cannot single out one Pulsar
    rule), so the egress override is removed; the source override now
    names `robot.motion.sample_source_mismatch`. A test checks every
    override in `config/*.json` against the OCSF catalog.
  - **Capture.** 802.1Q / 802.1ad frames whose inner tag the kernel left
    in place are no longer dropped by `AF_PACKET` as non-IP: the source
    hands each frame on behind a synthesized Linux cooked header
    (`LinkType::LINUX_SLL`, keeping `sll_addr`), the kernel BPF accepts
    tagged frames via `SKF_AD_PROTOCOL` and user space follows up to two
    tags (`BpfProgram::run_with_protocol` for tests). The `AF_PACKET`
    docs now say that a sensor box with a promiscuous capture NIC sees
    other hosts' mirrored traffic.
  - **Examples.** Go2-W, H1, H2 and R1 profile examples carry
    `/api/motion_switcher/request`; the sensor-box example's command
    sender is a labelled example operator PC (192.168.123.162), not a Go1
    internal computer; the `/arm_sdk` joint-firewall warning says to leave
    the channel out of `joint_config` (the profile envelope still checks
    torque, kp and step on every slot).
  - New rule ids (contract 2.1 OCSF catalog, correlation catalog):
    `robot.unitree.legacy_sender_flood`,
    `robot.unitree.legacy_sender_mac_mismatch`,
    `robot.unitree.legacy_port_rtps`, `robot.motion.command_type_mismatch`.

- Unitree decoders (`robodr-cdr`), review of the initial implementation:
  joint command frames are evaluated over **every** slot whatever the mode
  octet (`rt/arm_sdk` sends `mode = 0` and still moves the arms; a
  non-finite field in any slot poisons the frame); torque-only and
  position-gain commands are no longer "speed 0" — `MotionCommand` gains
  `joint_torque`, `joint_kp`, `joint_position_step` (filled by the ROS 2
  pipeline and the commissioning pcap reader from the previous frame on the
  channel) and `command_class` / `command_name`, the profile envelope gains
  optional `max_joint_torque`, `max_joint_kp`, `max_joint_position_step`
  (checked as `robot.motion.joint_over_envelope`; absent → a command using
  the term is `robot.motion.unverifiable_command`, Medium), and
  `robodr-commission` learns, caps (`--hard-cap-torque`, `--hard-cap-kp`,
  `--hard-cap-position-step`), locks, merges and diffs them; API calls are
  dispatched on the low 32 bits of `api_id` as the SDK server does, and an
  id outside `int32` is the new High finding
  `robot.motion.api_id_out_of_range`; API tricks / trajectories / unknown /
  malformed motion calls are `robot.motion.unverifiable_command` and
  control handovers the new `robot.motion.control_handover` (High); new
  velocity services Go2 `obstacles_avoid` `Move` and G1 `agv` `Move`, plus
  `robot_state` / `uwbswitch` handovers, R1 `SetArmTask` and the

  header no longer makes the decoder expect struct DHEADERs; `crc_ok` is
  documented as advisory (C++ padding can be indeterminate); legacy

### Security

- Fleet lifecycle and offline bundle, review fixes before the first
  release that ships them:
  - `install-bundle.sh install|verify --pubkey --tarball` verifies the
    tarball (and the release `SHA256SUMS.minisig` when it lies next to it),
    extracts it into a private `mktemp -d` and installs from there; an
    extracted bundle directory the script runs from must equal the signed
    content (a signed tarball next to a modified extraction was accepted
    before). The package installs `/usr/lib/robodr/install-bundle.sh` as
    the trusted verifier for upgrades; OPERATIONS 3 now says to verify
    before extracting.
  - Downgrades through `install` need `--allow-downgrade`; a per-unit
    security floor (bundle `security-floor`, ring `min_version`; only
    rises) is enforced by install and rollback with no override.
  - `rollback <version>` takes a version, never a path; `--blackbox-dir`
    refuses glob characters and is no longer word-split.
  - `robodr-enroll`: the token is refused on argv; the token file must be
    root-only. Rotations persist a `sent` mark and are cancelled at the SOC
    instead of being abandoned locally (a lost answer no longer blocks
    every later rotation). Approvals come from a separate SOC approval key
    and are valid at most 7 days. SOC key files must be root-owned in a
    private directory. Files for agentd get owner and mode on the
    descriptor before the rename, in a directory not writable by others; a
    damaged installed revocation list is reinstalled. Ring information
    issued in the future is refused.
  - Contract `robodr.fleet-api` draft v1 revised (§11): proof of possession
    of every key at enrollment, SOC-wide key uniqueness, cancel endpoint,
    authenticating key of uplink rotations (`401 wrong_key`), SOC key
    rotation and revocation, replay note; vectors regenerated (cases
    15-17).

## [0.1.0-alpha.1] - 2026-10-16

First integrated pre-release of the workspace. Nothing in it has run on a robot
or a live kernel yet. The verification status of each crate is in its README
and in `docs/PULSAR-INTEGRATION.md`.

### Added

- **Pulsar integration**: `robodr-sensor-ros2` aligned with the real Pulsar
  module API, and the `robodr-pulsard` daemon (Pulsar with the RoboDR modules
  registered).
- **RTPS / DDS parsing** (`robodr-rtps`): SPDP and SEDP, INFO_SRC
  attribution, disposal, DATA_FRAG, vendor ids. Split into a pure crate with
  mutation fuzzing, synthetic fixtures, a golden corpus and a cargo-fuzz
  harness.
- **Passive capture** (`robodr-capture`): pcap/pcapng decoders, read-only
  AF_PACKET with a classic BPF filter.
- **ROS 2 pipeline** (`robodr-ros2-pipeline`): a pure sensor pipeline, a
  capture source and the `robodr-ros2-watch` tool.
- **Commissioning** (`robodr-commission`): observe-mode learner,
  `learn`/`lock`/`diff`/`merge`/`check`/`signoff`. Learns services, actions,
  raw DDS topics and reader sets, takes pcap input, and validates on lock.
- **Motion**: a consistency detector for motion commands against feedback
  (`robodr-motion`) and the Motion Firewall core (pass / limit / reject,
  alloc-free hot path; `robodr-firewall`).
- **Response**: Cyber-Jidoka graded response planner (`robodr-responder`).
- **Evidence**: signed, hash-chained black-box recorder with
  store-and-forward export bundles (`robodr-blackbox`). The authenticator is
  HMAC-SHA256, a documented placeholder.
- **Findings**: OCSF Detection Finding envelope for `robot-edr.findings`
  (`robodr-ocsf`).
- **Agent**: first end-to-end decision chain, run offline, plus `robodr-replay`
  (`robodr-agent`).
- **Rules**: robot host rules rewritten for Pulsar's real rules engine, with
  an offline grammar-checked validator.
- **CI**: defence-posture CI with a `Cargo.lock` policy and `--locked`
  builds, cargo-deny, CycloneDX SBOM, reproducible-build check, air-gapped
  mirror support and fuzz smoke tests.
- Docs: roadmap and sprint plan, re-sequenced defence-first.

### Changed

- `robodr-events`: `Severity` is ordered and hashable. Motion checks fail
  closed, ROS 2 names are de-mangled, and observe mode is added. Wave 1
  adapted all crates to the events API (`Cow` rule, `MotionFeedback`).

### Security

Fixes from the wave-3 security and safety reviews:

- commission: poisoning gate, mandatory sign-off, profile seal, hard caps,
  safe file I/O (atomic, no-clobber, symlink-refusing).
- blackbox: anchor forgery, export cursor, crash recovery, forged head, lock,
  symlinks.
- rtps: fragments, attribution, leniency, CPU bounds.
- capture: passive-capture findings F7a/F7b/F7c/F8.
- ros2-pipeline: participant/source-IP binding, flood caps, ambiguity and
  not-inspected findings.
- firewall: angular bound, HoldLast, infinite envelope, observe mode,
  spoofer state.
- motion: direction, injected feedback, NaN.
- responder: bounded decoy influence on rate limiting, overflow and motion
  guard; honours `Deviation::mode`; per-(source, rule) rate limiting.
- agent: fail-safe evidence and clock handling, replay isolation, strict
  config.
- ocsf: allow-list taint neutralisation, dual rendering, flags; observe-mode
  fix.
- events: ROS names validated in profiles, malformed mangled names rejected,
  name-normalisation gaps closed.
- rules / supply chain: exec-path, fileless, Python and keystore bypasses
  closed; `--locked` CI.
- sensor-ros2: Pulsar lifecycle mismatches fixed. Status is documented as
  stub-verified.
